1. ROZSAH RELEASE
---------------
Verze 0.21.52 zachovava kompletni dvoustrankovy reporting pro vedeni zavedeny ve 0.21.51 a pridava pripravenou serverovou funkci "Kdo je prave online a kterou aplikaci pouziva".

Do tohoto releasu nebyl pridan zadny monitoring obsahu prace, promptu, materialu, URL, IP adres, zarizeni ani historie aktivity.

2. LIVE PRESENCE - CO JE IMPLEMENTOVANO
---------------------------------------
- Ve Sprave je novy panel pro plneho spravce.
- Panel zobrazuje pouze:
  - zobrazovane jmeno uzivatele,
  - prave pouzivanou aplikaci.
- Funkce je dostupna pouze plnemu spravci, nikoli uciteli, operatorovi ani nahledu kolegy.
- Chranene aplikace pouzivaji centralni platform-runtime AI Studia, proto neni nutne kvuli heartbeat upravovat kazdy repozitar aplikace zvlast.
- Presence modul se nacita dynamicky jen pri skutecne aktivni serverove funkci; v GitHub Pages profilu nevstupuje do bezne spousteci cesty.

3. MINIMALIZACE DAT A SOUKROMI
------------------------------
Heartbeat z klienta odesila pouze:
  schema + appId

Klient NEODESILA:
- jmeno,
- e-mail,
- userId,
- verzi aplikace,
- klientsky cas,
- prompt,
- obsah materialu,
- studentska data,
- URL,
- historii aktivity.

Identitu uzivatele musi server odvodit z overene skolni session. Cas posledniho heartbeatu urcuje server. Zaznam je pouze docasny; navrzeny TTL je 120 sekund a data se nemaji ukladat do historie ani mesicniho reportingu.

Heartbeat se odesila jen z viditelne a aktivni karty. Pri vice kartach tak posledni aktivne pouzivana aplikace reprezentuje aktualni stav.

4. SERVEROVY KONTRAKT
---------------------
Pripraven je kontrakt pro:
- POST /api/v1/presence - heartbeat aktualni aplikace,
- GET  /api/v1/presence - aktualni snapshot pro plneho spravce.

Podrobna specifikace je v:
  docs/LIVE-PRESENCE-SERVER-CONTRACT.md

DULEZITE: serverovy backend endpoint neni soucasti tohoto repozitare. V dodanem buildu zustava feature flag livePresence=false. Funkce se ma zapnout az po implementaci a otestovani backendu na skolnim serveru.
